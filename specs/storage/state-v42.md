# State42: frozen remote extension installation sources

Approved on 2026-11-17. The 41→42 transaction rebuilds only `extension_plans`, preserving every previous column, row, key, foreign key, owner index and immutable-trigger comparison. The source CHECK additionally accepts `remote_extension_source`. Its `remote_source_json` must be present exactly for that source kind, valid JSON and at most64KiB; other source kinds keep NULL. The validated evidence includes requested canonical index URL, selected version, index fingerprint, pinned artifact URL and ZIP SHA256. It joins the immutable comparison; it is never rebuilt from changing remote content during review or detail reads.

SQLite foreign keys and legacy rename behavior are changed only on this migration connection to permit the documented table rebuild while dependent journal triggers temporarily refer to the old table name. All foreign keys are checked inside the transaction before commit; foreign keys return ON and legacy_alter_table OFF. An injected failure rolls back complete schema, triggers, rows and user_version. A failed initializer closes its connection. The initializer applies the preserved original migrations followed by this increment and can reopen without regranting or rewriting state. Old Core rejects State42.

No Config, permission name, extension ABI, credential table or historical migration changes. Original running data is not upgraded by development. Exact source/RPC boundaries are in [source-v1](../extensions/source-v1.md); State42 does not authorize upgrades, auto-update or publisher trust.
