# 存储库配置文件 v1

扩展名来自产品元数据 `formats.repository_list_extension`：`.alcomdrepositories`。这是完整存储库配置交换文件，旧 ALCOM 不支持；GUI 另提供旧 VCC TXT 兼容导出及原有 TXT 导入。规范结构见 [Schema](repository-configuration-v1.schema.json)。

```json
{
    "format": "alcomd-repositories",
    "version": 1,
    "repositories": [
        {
            "source": { "kind": "remote", "url": "https://example.test/index.json" },
            "configuration": {
                "displayName": "My repository",
                "priority": 1,
                "enabled": false,
                "disabledPackageIds": ["com.example.package"]
            },
            "credentials": null
        }
    ]
}
```

文件为 UTF-8 JSON，可有 BOM；最多 1 MiB、4096 个来源。包含全部已登记远程、本地及内置存储库，独立于 GUI 页码和筛选。来源只存实际 HTTP(S) URL 或本地路径；不包含索引、软件包归档及 Core 内部 ID、修订、凭据引用。包关闭清单保留暂未出现于索引的 ID；未列出的包启用。

`displayName` 为自定义显示名，null/省略/空白表示清除覆盖并使用索引名称。`priority` 越小越优先；同优先级保持，数组位置用于同优先级的稳定导入顺序。配置开关沿用 Config13 的数量及包 ID 边界，不以当前包列表或依赖关系限制导入。

导入先按完整来源匹配当前实例，应用文件内的配置并保留文件外的存储库。新来源复用既有注册流程取得本机 ID，开关映射到该 ID。文件内来源优先排列，其余来源保持相对顺序；无需改变的优先级保持数值，过大的外部数值按相对顺序规范化。已有项不为恢复配置重新下载索引，新项按既有注册规则读取来源。本地文件在另一台机器上不存在时逐项报错，不猜测替代路径。重复来源及未知版本拒绝。

导入预览提供“覆盖已有存储库配置”，默认开启。关闭时仅新增，文件中已有的来源跳过，原名称、顺序、开关、认证及修订保持；新来源按文件相对优先级追加。文件格式本身不携带导入策略，策略由本次导入请求决定。

认证项 `credentials.headers` 沿用现有请求头校验；匿名项为 null/省略，本地项只能为 null/省略。认证明文仅由 Core 写入用户确认的新文件，不经 RPC、日志或普通错误返回；导入已有来源时也会恢复或清除认证。GUI 沿用导出私密提示与确认。

预览不下载或登记，导入前重新读取文件并比对字节指纹；变化要求重新预览。停止后不再接纳新项，已接纳项完成，逐项返回新增、更新、已存在、失败或未处理。已完成修改保留，不宣称批量回滚。名称及顺序在 SQLite 内一次事务保存，开关由现有设置 CAS 保存；后一步失败明确报告可能未完整应用，用户核对后重新预览。重复导入同一配置不修改名称/优先级或设置修订。

名称及优先级冲突检查只比较实际受影响字段；无关索引刷新不会引发配置冲突。读取可并发，登记写入逐项串行，写入结果未知时停止后续登记并返回未知项，沿用已有列表导入的部分结果约定。

导出默认包含内置和本地来源，不排除关闭的来源。指纹绑定实际配置及认证内容，普通索引刷新不让相同配置的预览过期。只新建用户选择的文件；不覆盖已有文件，不向 Core 数据或已登记项目内写文件。旧 TXT 保持原范围及认证语法，仅保存可表示的用户远程来源，不能保留显示名、排序及开关。
