## 最终行为

| 项目 | 修正及回归 |
| --- | --- |
| G1 关闭来源 | Core目录和候选存储接口接收同一配置快照，SQLite先行过滤关闭仓库、用户源和规范版本中的预发布；未关闭来源的完整性独立计算。Plan准备返回前、Apply复验、执行准备及发布前检查当前来源资格，关闭后旧计划失效，显式来源及请求预发布选项不能绕过。13项正式用例含准备归档期间关闭来源的竞态及隐藏未索引仓库不阻挡可用源。 |
| G2 撤回状态 | 共用撤回字段解析识别顶层yanked与vrc-get.yanked的布尔/有界原因文字，仓库和本地源均传入求解资格；现有仓库展示元数据中的撤回状态也参与目录读取。资格不依赖可选搜索/显示字段是否可解析，避免显示解析失败清除撤回状态。普通新依赖拒绝撤回版本。 |
| G3 批量范围 | 从所选意图构造增量请求，复用未选包现有版本/依赖，不为无关包取来源，不删除无关孤立包。批量重装保留原图、原清单和传递资格；混合意图仍拒绝破坏保留依赖。单项及单项批量入口的无关来源反例均覆盖实际Apply。 |
| G4 旧依赖清理 | 普通安装/升级/降级及批量变更对受影响包的旧依赖闭包做清理，保护剩余直接根、已有本地包依赖和本次安装目标；共享依赖与无关孤立包保留。新旧图独立计算，不对整个项目清扫。 |
| G5 缺失目录重装 | 按实际目录/版本冻结Install或Replace，Plan后出现/消失均拒绝。固定清单摘要相同则保留原字节，沿用原事务发布、过期检查与回滚保护。单项/批量、初始有/无目录均通过真实Apply及外部目录变化拒绝回归。 |
| G6 本地提供方 | 有界读取的未锁定包快照保存实际版本和依赖，Resolve跳过已存在的本地目标；新增包需要该本地提供方时复用，既不下载也不覆盖。新依赖版本不兼容仍拒绝，不放松既有严格合同；真实缺失根保留原错误，不把空请求误报为plan_too_large。 |
| G7 固定版本恢复 | Resolve/Reinstall/批量重装仅对原locked的精确版本放行撤回/Unity资格，不把这个例外扩大到新依赖。精确匹配包含build标识，避免选到同优先级的其他归档。关闭来源优先；不使用allowUnityIncompatible新开关，不放宽摘要、来源消歧、权限或恢复校验。 |

普通包仍只枚举Packages直属目录并读取有界清单，不扫描payload。内部元数据指纹域从v3更新为v4（指纹修订号），旧未执行包计划需重新生成；Unity迁移原内容指纹、整体图构造和归档/恢复边界保持独立。没有DB迁移或额外项目包副本。已接受事务先恢复必要文件系统状态，再检查新准备/发布资格，避免关闭来源挡住恢复清理。

SDK/Resolver专用Unity规则仍是此前明确不采用的差异，不在本轮七项范围。原失败呈现、100ms导航、按包准备版本、已加载页面后台完整更新保持。GUI源码与SDK/协议类型未改。

## 失败轮次与调整

- 内部目录/候选端口改为必填策略快照，首轮all-targets检查指出存储单测的13个旧调用缺少参数；已逐一同步，无旧接口或默认放行的兼容实现。
- 首轮VPM库171通过、4失败：旧“已安装”计划夹具只有locked记录、实际目录缺失，新G5正确生成Install；补成真实已安装目录，保留Replace断言。混合重装/卸载保护夹具补充原已安装锁定图的依赖，保持拒绝断言；不再拿同版本仓库重新声明的依赖代替原锁定图。后轮1项因原夹具省略dependencies字段而与保留原元数据的新合同冲突，补齐夹具实际空依赖，保留原断言。最终175通过。
- 新增正式用例首轮8通过、2失败：普通注册已经建立索引，未索引场景改用真实bootstrap写入口；本地源冻结缓存允许登记删除后继续使用，单靠目录过滤未阻挡全局关闭，补当前配置资格复验后通过。没有移除冻结归档安全回归。
- 候选快照旧测试给未安装的直接声明断言两项移除，与已批准的“依据locked安装事实”冲突。现断言未安装不可移除，并另验证实际安装记录仍有两项移除/重装；保留缓存读取次数、分页、排序和过期断言。
- 新测试首次严格Clippy指出85处unwrap调用，改为带诊断的expect/expect_err，没有抑制lint；最终严格检查通过。

失败日志均保留在同一证据目录，没有放宽生产权限、摘要或恢复门禁来使测试通过。
