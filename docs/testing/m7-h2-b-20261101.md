## 模板分页模块

GUI adapter 保持 `limit=100`，仅透传现有 opaque cursor。TemplatesPage 复用既有 PagedItems；
创建选择器保留已加载模板和选择，失败后重试同一 cursor。打开/关闭/client 代际及在途请求票据
阻止旧页响应修改新草稿。首读失败与空列表分开，Retry 明确重读；弹窗首次显示后保持本次会话
可见，避免 Retry 等待触发关闭。没有新增 RPC、公共 DTO、权限、Schema、依赖或 native API。

浏览器使用确定性 client fixture，101 个不同模板；后页选择发出对应 TemplateId/revision，
Apply 后按 fixture 返回的 ProjectId 导航。它证明 GUI 接线，不代替真实 daemon/文件写入。
本模块尚不提供完整的真实模板 Plan evidence 或模板任务终态验收，后续模块继续补齐。

## 模板确认、任务与请求所有权

三类 review 消费 Core 顶层白名单字段，统一校验 UUID、安全整数 revision、digest、action/state 和
对应对象上下文。import 的名称/版本绑定 inspect 的新 digest/manifest；derive 的名称/版本来自本次
冻结请求，来源 ProjectId/revision 取 Plan；两个创建入口共用 templateRevision、目标 leaf 和
must-be-absent 校验。父目录只作为冻结请求上下文，不展示不透明 filesystem identity。
缺失、错误类型或对象/digest 不匹配时返回有界错误，不出现可执行 Apply。

本页显式接受的 OperationId 由现有页面保存，每个 ID 只有一个既有 OperationFollow。弹窗显示
被动进度，关闭不销毁页面跟踪；只在同一任务 succeeded 后刷新。失败/取消不刷新或报成功；
首次及后续进度读取失败继续按原 750 ms 读取同一 ID。client、ID、卸载代际均约束迟到响应，
不重新 Plan/Apply，不自动取消 Core 任务，也不新建全局 task store、历史表或轮询引擎。

模板行的现有 controller 位于 PagedItems 外，冻结 selection/session/snapshot。旧任务成功使
分页重建时，新草稿的字段、Plan 和 busy 保留；关闭后的 controller 保留到下次显式打开，
让共享 Dialog 完成 closed/updateComplete 焦点恢复。原行已断开时使用仍可用的创建按钮。
Projects 创建在刷新后再次核对原草稿代际，旧成功不会关闭或导航新草稿；定位只使用成功任务
返回的 ProjectId。未知 Apply 保留不确定提示并禁用原 Apply，不用新幂等键自动重发。

## 仓库与用户包模块

User Package 行内 Details 使用现有 get 和共享读取状态，显示当前名称、packageId、版本与源目录；
revision/摘要为次要信息。关闭/重开隔离旧读取，并按共享 Dialog 生命周期返回原控件。没有新增
导航、RPC、权限、Schema、依赖或 native API。

仓库和用户包既有 inspect/register/refresh/remove 路径保持；浏览器使用有状态的资源 fixture
验证确认、取消、CAS 和 last-known-good，不为测试增加产品旁路。

- `resources-module`：**18/0，1.5 分钟**，包含 12 项资源场景和 6 项既有 package/source 回归。
  运行前后 78 项输入 hash 一致，见 resources-module-inputs-before/after.json。
- 同轮类型检查发现新 repository fixture 缺少必需 refreshedAtMs；补齐后
  `template-actions-check` 的 GUI 类型、Material 与三语言检查通过，856 项词条。
- Details 读失败重试同一 ID、迟到 snapshot 隔离、chooser 取消不 enroll、完整 enroll/get/refresh/
  取消与确认 remove、缺 capability 零调用、两类仓库确认/包后页/取消与确认移除、refresh 失败
  保留旧 catalog、CAS 显式重读及无效/重复源均在该组覆盖。
- 浏览器不证明真实目录 hash、外部文件产物或 daemon 写入；这些仍需隔离 native 场景。

## Native 输入准备

已按公开 Template Bundle v1 构造同 ID 的 A/B 两份 Stored ZIP、有效最小 Unity payload、
带排除项的未登记 source project、loose user-package 和 local repository JSON。
位置为 `target/m7-h2-b-20261101/native/fixture-inputs.json`，保存所有路径、摘要和模板 UUID。
两份 bundle 通过语义 metadata 区分，payload tree 相同；尚须由真实 Core inspect 验证，
不因离线打包成功就认定 native 或 parser 通过。未直写数据库、cache 或已登记项目。
