# M7 软件包展示补齐：正常读取项目文件

状态：2026-11-08 所有者明确要求“撤掉这次额外加的数据库副本和补采流程，按 v3 那样正常读取项目软件包信息”。本合同取代此前项目展示持久化与 GUI 补采方案，本地实施、定向验证和 Core/GUI 更新已完成，详见[验证记录](../testing/package-direct-read-20261108.md)。v3 仅用于行为核对，实现独立编写。H7 人工签收保持待定。

## 当前有效读取合同

- GUI 在正常的软件包候选请求中取得 Core 读取的项目信息，不先调用 projects.refresh，不填充数据库，也不新增独立提示、补采按钮或后台填库流程。保留 100ms 首屏预算，慢请求仅延后包列表。
- Core 在授权、项目 scope 和请求/revision 校验后，通过现有有界项目读取器获取项目清单、当前锁定版本与本地 package.json。文件是本次展示信息的来源；候选查询不修改项目、项目登记快照、revision、事件或操作日志。
- 新的普通首读重新读取项目文件。搜索、版本选择和分页可使用本次结果的内存快照，按 Principal/Project/登记 revision 隔离；仅保留一份、受既有 4096 包/16MiB 上限约束。新首读观察到变化会改变候选指纹，旧 cursor/expectedSnapshot 被拒绝。内存丢失可重新读取并校验指纹，不写持久副本。
- 登记记录修订仍由既有项目用例持有，文件观测另外进入候选 fingerprint；既有 Plan/Apply/recovery 的冻结授权与文件过期检测保持，不以展示读取改写它们。
- 保留来源关闭/缺失等价、已安装事实、名称/说明/关键词/别名、合法链接、撤回提示、SDK/legacy 展示取舍、精确来源、安装样式和 Core Unity 分组。

## 公开合同与清理范围

沿用 packages.candidates.v2 与同一查询方法、四项读权限。summary 增加可选 requestedRange（最长 256 字节），与本次正常读取的 installed 信息共同供 GUI 展示，避免拼接旧登记事实。既有 presentationState/presentationComplete 只表示本次可读信息的质量，不再对应数据库观测或补采流程；缺失已安装撤回信息仍表示未知。

按所有者明确的撤除要求删除以下两张表及其读写模块、观察 revision、缓存失效记录和所有项目发布钩子：

- project_package_presentations
- project_presentation_observations

保留既有项目登记/事务/Plan/历史和仓库索引；repository_package_versions.presentation_json 属于仓库规范化索引，继续供搜索与展示使用。State30 新建结构不再创建项目副本；State31 只清理已有开发数据中的上述两表，随后只有一种正常读取实现。编号为内部数据格式序号，不是产品发布版本。真实数据操作遵循已授权范围，启动前保留备份，不恢复旧数据库覆盖用户修改。

## 验收

- 用真实项目文件证明：修改包名称/锁定版本/依赖范围后，普通查询立即读取最新值，无 projects.refresh 前置步骤；数据库项目快照、事件、幂等记录及日志不变。
- 分页使用内存结果；新普通读取后旧游标过期。权限与 scope 在文件访问之前校验，仓库来源/设置修订的隔离不降低。
- 删除表后的登记数据、仓库索引、事件、计划和冻结授权保留；历史迁移、M4 和恢复回归继续执行。
- 前端检查/构建、相关浏览器、受影响 Rust 测试、fmt、严格 Clippy、公开 DTO/Schema/SDK 与仓库检查通过后交付。测试使用现有 workspace rusqlite 增加开发依赖以核对只读数据库状态，没有新增生产依赖或库版本。
