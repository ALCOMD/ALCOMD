# Extension-provided MCP tools v1

Owner approved implementation on 2026-11-16. See the M8 ExecPlan for authority and dependency approval.

- Signed optional Manifest section `[mcp] tools = "component/mcp-tools.json"`; catalogue is version 1 and contains at most 32 declarations, total UTF-8 <=65536 bytes. Names are lowercase ASCII identifiers <=32 bytes. Public names are `alcomd_ext_` + the first 20 lowercase SHA256 hex characters of ExtensionId + `_` + local name; installation rejects collisions.
- A declaration has name/title/description/inputSchema/outputSchema/uses. Uses are the closed project-list/get, package-plan-uninstall/apply, operation-get/cancel operations. Core derives required permissions and execution effect; a tool cannot combine distinct persistent effects. A tool's declared operations are an invocation allowlist, not grants.
- MCP clients retain the existing eight global business capabilities. Extension grants additionally require an explicitly granted mcp.tools.provide (declared required or optional) and the operation's business capabilities. No project, extension, or per-tool client grants are introduced. Authenticated zero-business-authority clients may call published pure-computation tools only.
- Core `mcp.tools.catalog` returns deterministic, permission-filtered builtin/extension descriptors with opaque credential/OAuth-and-snapshot-bound cursors. Name lookup uses the same method. `extensions.mcpTools.call` accepts name and arguments. No caller-supplied identity is accepted. Capability is mcp.extension-tools.v1, published only after real wiring validation.
- Independent provider/core WIT interfaces do not modify the frozen v1 world or activation enum. Provider invocations require no UI or background.run. Core retains actual MCP identity, current credentials/OAuth and extension lease, verifies both sides again at business acceptance, and preserves resource ownership.
- Core supplies control fields for plan/apply/cancel tools. Persistent calls require idempotency_key; Apply also requires original plan_id/expected_revision/confirm=true. Only one persistent action is admitted. Core effect evidence is outside guest data and cannot be forged by guest output.
- State38 records the principal/name/key/input digest, frozen tool/package/publisher, call state and accepted Core effect references atomically with the existing business transaction. No secrets, raw arguments or guest output are persisted. Explicit same-key recovery never reruns guest; changed input conflicts. Cancellation, trap, invalid output or connection loss never erase an accepted effect or automatically cancel/retry business work.
- JSON Schema 2020-12 only, local non-circular references, no external resolution or x-mcp-header. Definition/arguments/result each <=65536 bytes. Trusted Host validates under existing bounded process/call quotas; list never invokes guest. Results use data plus Core-generated coreEffect evidence. Unknown write outcome remains core_write_outcome_unknown.
- Disabled/uninstalled/quarantined/revoked providers stop new calls; already accepted Core work follows existing recovery. Stable errors and safe diagnostics never include credentials or raw payloads.


Implementation bounds: root-only schema identifiers, local JSON Pointer/anchor references (including URI-encoded fragments), schema depth <=64 and policy traversal <=16384 nodes. Schema annotations and literal data are not interpreted as references. A persistent tool uses a literal root object with properties/required/additionalProperties/$defs/$schema/title/description; nested schemas retain 2020-12 validation. Reserved Core control fields cannot be supplied by that declaration. Argument fingerprints sort object keys and preserve the values observed by the guest.

OAuth retains its already approved non-empty consent contract: zero-grant pure calls are covered by credential/STDIO/Bearer authentication; OAuth pure calls need an existing non-empty capability ceiling. No new OAuth scope, empty-scope token model or implicit business grant is introduced by this feature.
