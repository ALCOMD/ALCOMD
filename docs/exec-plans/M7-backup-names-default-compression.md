# M7 备份文件名与默认压缩修正

所有者报告默认备份体积不同和UUID文件名，核对实际归档后选择“默认等级5：体积更接近v3”，并接受新备份使用“项目名＋时间”。本项继续当前M7；不以正在运行的旧候选CI作为本增量验收。

## 有效行为

- 新配置和未指定压缩的默认备份使用现有level5。0/1/3/5/7/9真实含义不变；显式保存的设置、单次选择和已接受任务不被重写。当前用户如需立即采用5，经既有settings.update正常保存，不直接改配置文件或数据库。
- 用户备份目录的新归档使用项目目录名和创建时间（本地时间，含毫秒）组成的ZIP文件名。非法文件名字符替换、过长项目名截短，保留中文。最终名称进入内部ArchiveReady证据，发布/重启恢复不重新推导名称；冲突不覆盖已有文件。
- 已有UUID归档和旧任务证据继续沿原定位恢复，不搬迁、不重命名用户旧文件。内部objects的旧backup-v1定位保持。公开RPC、manifest、数据库Schema、权限不变；归档规范同步外部文件命名说明。
- 恢复仍由存储定位、原文件身份、SHA-256、manifest及Plan/Apply证据约束；友好文件名不是身份。不得以名称变化绕过既有复制/替换/路径穿越等保护。

## 依赖与替代方案

alcomd-vpm直接使用工作区锁文件中已有的chrono 0.4.45，仅启用std/clock，用于可靠本地日历格式化。已核对MIT OR Apache-2.0许可、维护仓库及现有锁定版本；不升级传递版本。自行实现日历/时区算法增加维护和跨平台错误风险，沿用数字epoch不符合可读时间要求。成本是增加一个直接依赖及其现有时区依赖的直接使用；不引入旧产品代码。
