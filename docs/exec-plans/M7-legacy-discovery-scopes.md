# M7 普通软件包旧资源读取范围

2026-11-09。所有者明确要求更新与v3一样不重复扫描既有旧资源声明，随后决定保留官方GUID查找规则，优化扫描性能并修复大meta失败，询问重装行为。仅声明路径/限制目录深度的候选均不采用。只推进当前M7；此前GUI名称和确认弹窗修改保留，不提交、推送或更新运行实例。

## 已授权：更新跳过既有声明

对同一已安装包，更新继续声明的legacyFiles/legacyFolders路径不再次发现或清理；仅新增声明参与检查。比较归一化路径，不因GUID变化对既有路径重复处理。复用/核对Packages中有界package.json元数据及原冻结项目指纹。Plan、Apply发布前和发布后使用同一份原已安装声明，不能替换后用新版本声明代替旧依据。旧包依赖、legacyPackages、来源资格及事务恢复保持。无需新增公共字段、权限或数据库迁移。重装按所有者后续明确批准的下节行为处理。

## 所有者后续批准：重装重新检查全部声明

所有者提出重装应等效卸载后按原版本安装，并明确回复“好，那就这么实现”。本次只扩展所选包的旧资源重新发现：单包、全部重装及批量中显式重装目标检查该包完整声明，必要时递归GUID发现；混合批量内其他更新包仍排除既有声明。保持原版本、直接/传递依赖身份、原有冻结图与来源资格，不真的拆为两次事务；仅确认后的冻结旧资源目标进入删除，发布失败回滚包与旧资源。

重装目标通过内部`legacyReinstallPackages`有序去重列表冻结在既有ChangeSet JSON，限制为有固定source和目标版本的install/replace mutation，进入原摘要与恢复读取，不投影至公开RPC DTO。沿用formatVersion 4，无新公开字段、方法、权限、SQL表/列或数据库迁移。普通项目元数据指纹升为v6以拒绝旧未执行计划；已进入事务的恢复继续按原冻结证据处理。此项是所有者主动选择与v3不同的重装语义，不宣称与v3完全一致。

## 已授权：保留递归GUID发现，优化读取

依据[官方清单说明](https://vcc.docs.vrchat.com/vpm/packages/#vpm-manifest-additions)及[VCC 2.3.0说明](https://vcc.docs.vrchat.com/news/release-2.3.0/)，路径缺失且有GUID时仍可递归找到已移动/改名的旧资源。没有GUID时只按声明路径。不引入浅层限制、静默截断、后台索引或缓存副本，不把未充分检查的状态当作不存在。

- 两处GUID发现/不存在证明共用流式meta读取：固定8KiB输入缓冲和少量GUID状态，不按meta总长度或行长度设置原64KiB拒绝条件，也不把整个导入设置保存在内存。
- 完整检查UTF-8与GUID声明，保留迟到重复GUID/非法尾部拒绝；保留文件身份、长度、修改时间、目录变化、重解析点、读取总量64MiB和条目65536上限。超出整体安全预算仍明确失败，不能假装证明不存在。不读取未选中模型/贴图payload。
- 同一Apply证明阶段的多个包合并GUID集合，只遍历一次Assets；固定清单/归档声明先合并再证明。保留Plan与事务写入前后的必要复验，不跨阶段缓存失效证据，也不因先找到一个目标而跳过重复GUID检测。
- 仅更新内部读取实现；无新RPC字段、SQL Schema、权限名称、生产依赖或迁移删除清单，不收窄现有GUID发现语义。GUI失败呈现及100ms保持。
