# M7 VPM 七处行为修正

2026-11-09，所有者明确要求“把这7处问题都修复，关闭来源按我之前的要求处理，其余按v3的行为对齐，完成相关验证后更新Core和GUI”。该授权覆盖前轮审计列明的七组行为及固定版本恢复策略修订。完成后所有者另行授权本项本地提交。只推进M7，不推进H7/M11签收，不推送。

## 有效合同

1. 来源关闭是Core资格，不是GUI隐藏。仓库、本地用户源及关闭的预发布版本在候选目录、求解、Plan/Apply及提交前复验中排除；已安装事实和无来源卸载保留。隐藏的未建索引仓库不阻挡可用来源。目录读取端接受同一配置快照，禁用来源不能通过显式来源选择绕过。
2. 顶层yanked与vrc-get.yanked布尔/有界原因文字统一为撤回状态，仓库和用户源的展示与普通依赖求解一致；普通安装、升级及新依赖不自动选择撤回版本。
3. 批量操作按所选意图增量求解，保留未选包现有版本和元数据，不要求无关来源，不清扫无关孤立包；纯批量重装只准备所选固定版本。混合意图继续拒绝破坏保留依赖，不扩大已有纯卸载例外。
4. 安装/升级/降级及批量变更仅清理所选变更旧依赖闭包中不再使用的锁定包，保护其他根与未锁定本地包，保留无关孤立包。
5. 重装时按实际目录状态生成Install或Replace；冻结缺失与目录身份，Plan后变化拒绝，沿用原事务/恢复及摘要校验。
6. 未锁定本地包可提供已存在依赖，Resolve不下载或覆盖它们；仍读取有界清单及直属目录，不扫描payload。真实缺失依赖保留准确错误，不以空请求覆盖成plan_too_large。
7. Resolve/Reinstall对已有locked中的精确版本按v3恢复，固定目标不套用新候选的yanked/Unity过滤；新添加依赖仍执行普通资格。关闭来源/预发布的用户要求优先，来源身份、歧义、摘要、权限和冻结证据继续校验。现有allowUnityIncompatible仍仅用于原三个手动接口，不新增公共开关。

无新增公共RPC字段、权限、数据库Schema/迁移或生产依赖；内部应用/存储目录接口同步更新，不保留旧接口并行。若冻结内部证据需要调整，同步持久序列化和复验；旧未执行包计划可要求重建，已接受任务保留恢复安全。

SDK/Resolver专用Unity规则是此前明确未采用、且本轮七项之外的差异，继续保持。失败提示策略、100ms导航、版本按包准备、后台完整更新保持。
