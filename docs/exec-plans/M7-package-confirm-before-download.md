# M7 软件包确认后下载

2026-11-10。所有者在核对 v3 后明确批准本方案：普通包 Plan 仅依据固定来源元数据计算版本、依赖、兼容性及旧资源清理，确认后 Apply 才获取归档、验证摘要与包清单；普通更新跳过已有旧资源声明，重装保留完整声明检查。确认窗口不展示普通未更新项。

## 实施合同

- 移除普通安装、更新、降级、解析、重装和批量 Plan 的归档获取及未知摘要下载。仓库旧资源声明仍按已登记来源身份及清单指纹固定，不以新的仓库观察替代原计划。已有本地用户包只读其已登记的拥有归档。
- 仓库来源的 archiveSha256 改为可缺省，表示来源清单尚未提供且本地尚未固定归档摘要；用户包摘要仍必需。公开 DTO、Schema、桥接及 GUI 类型同步。此为上文已批准方案的必要合同调整，无新增 RPC 方法、权限、SQL 表列或生产依赖。
- Apply 下载未知摘要归档并将实际摘要绑定到同一仓库修订/包清单/URL，持久化既有摘要记录；计划本身不改写。已有摘要仍严格校验，冲突拒绝。项目写入前复验来源、项目、归档依赖、兼容性及实际旧资源声明，出现计划依据差异明确返回 PlanStale，不扩大删除或重新求解。
- 所有首次包目录/清单写入仍在既有事务和回滚保护下。项目暂存区和日志可在执行准备阶段创建。旧未执行普通计划通过项目元数据指纹版本失效；已进入事务的恢复继续使用原冻结证据。
- 经过来源/旧资源准备的新普通计划（含空清理范围）固定 formatVersion 4，防止归档新增声明落入旧的“仅证明不存在”语义。索引确认过的清理声明仍为权威；归档省略不会撤销它们。已确认执行固定的本地摘要可被同一源的旧计划复用，恢复不必重新做首次下载。
- 项目创建和 Unity 迁移的独立归档准备流程保持原冻结要求，不因普通包 Plan 的调整推迟其准备边界。

## 验证

使用隔离项目和本地 HTTP 服务证明 Plan 不请求包归档、Apply 才请求；覆盖有/无发布方摘要、摘要不符、归档依赖和旧资源声明不符、更新既有声明与新增声明、重装、混合批量及回滚。同步协议、Store、VPM 和 GUI 定向回归，记录实际通过和未执行范围。未获提交、推送或更新运行实例授权。
