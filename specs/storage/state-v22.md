# State22 template removal and project creation

The approved State21 cutover deletes the legacy `templates` and `template_plans` tables, indexes, and triggers. It also deletes the three legacy template operation kinds, their shared journal entries, idempotency and operation events, all template aggregate events, and their operation-log rows. Template-specific idempotency methods and template log actions are removed even when they have no associated operation.

The Store rejects the cutover when any legacy template operation is nonterminal, including `interrupted` and `recovering`. It checks this before migrating an existing State5–21 database so the previous Core can still finish or cancel the operation. The Store checks again inside the immediate removal transaction. Non-template child tables remain in place while the parent operation table is rebuilt. The Store checks all foreign keys before committing and restores enforcement. Existing project rows, project events, unrelated operations and their references, retained row identities and the Events and operation-log sequence watermarks survive the cutover.

`projects.create` uses the existing operations, operation journal and idempotency tables. Acceptance reserves a project ID and records the canonical parent and its identity. If a declaration or package resolution is required, the operation journal keeps its frozen evidence in bounded JSON chunks. The publication-intent checkpoint rejects new cancellation and survives a restart. Registration, the terminal task transition and their events commit in one transaction.
