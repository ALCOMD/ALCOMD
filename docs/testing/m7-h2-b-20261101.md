## 模板确认、任务与请求所有权

三类 review 消费 Core 顶层白名单字段，统一校验 UUID、安全整数 revision、digest、action/state 和
对应对象上下文。import 的名称/版本绑定 inspect 的新 digest/manifest；derive 的名称/版本来自本次
冻结请求，来源 ProjectId/revision 取 Plan；两个创建入口共用 templateRevision、目标 leaf 和
must-be-absent 校验。父目录只作为冻结请求上下文，不展示不透明 filesystem identity。
缺失、错误类型或对象/digest 不匹配时返回有界错误，不出现可执行 Apply。

本页显式接受的 OperationId 由现有页面保存，每个 ID 只有一个既有 OperationFollow。弹窗显示
被动进度，关闭不销毁页面跟踪；只在同一任务 succeeded 后刷新。失败/取消不刷新或报成功；
首次及后续进度读取失败继续按原 750 ms 读取同一 ID。client、ID、卸载代际均约束迟到响应，
不重新 Plan/Apply，不自动取消 Core 任务，也不新建全局 task store、历史表或轮询引擎。

模板行的现有 controller 位于 PagedItems 外，冻结 selection/session/snapshot。旧任务成功使
分页重建时，新草稿的字段、Plan 和 busy 保留；关闭后的 controller 保留到下次显式打开，
让共享 Dialog 完成 closed/updateComplete 焦点恢复。原行已断开时使用仍可用的创建按钮。
Projects 创建在刷新后再次核对原草稿代际，旧成功不会关闭或导航新草稿；定位只使用成功任务
返回的 ProjectId。未知 Apply 保留不确定提示并禁用原 Apply，不用新幂等键自动重发。

## Native stale 失败与 Core 接受边界修复

旧 GUI 创建 Plan 冻结派生模板 rev1；另一正式 CLI 将同一临时模板推进至 rev2 后取比较基线。

H2B-Stale-Uncreated 目标目录留下五个创建文件。因此首轮 native **未通过**，不能用完整
Chromium 或前面正常路径的通过覆盖。

targetRemainsAbsent=false。该失败任务、目录、原 Plan、日志及截图保持原样，没有手动清库、
删除残留或改验收条件。正式 CLI 首次带显式 true 的调用在参数解析阶段 exit 2，读回仍为 rev1；
随后按该 CLI 当前支持的省略形式写 favorite=false，确实返回 rev2。原始结果分别记录，
本轮不修订范围外的 CLI 布尔参数语法。

原因是登记 revision/digest 在目标发布后的最终提交才检查。修复将同一检查复用于 Store 的
Immediate 接受事务，在创建 Operation、journal、幂等响应前拒绝已知失效的未接受 Plan；
原先已接受请求的重放仍优先，最终提交检查保持。三类模板共享该边界，不新增 RPC、错误码、
DTO、Schema、权限、依赖、迁移或 native API。

  before accepting a task”，实际却返回 schedule=true 的 TemplateApplyOutcome；0/1。
