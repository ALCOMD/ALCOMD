# 软件包计划输入与卸载计算修正

2026-11-09，M7 范围内的 Core 修正。所有者明确要求失败处理保持现状，并指出全包内容扫描及卸载重求解仓库依赖的不合理开销。本轮没有修改 GUI、失败提示、公共 RPC 形状、权限、数据库或生产依赖，也未提交、推送或替换运行程序。

## 有效行为

- 普通包计划和 Apply 复验只读取项目身份、VPM/UPM 清单、已锁定包目录身份及有界 `package.json`。不递归扫描包目录，不读取脚本、贴图等内容。
- 内容文件独立编辑不再使依赖计划失效；清单、包元数据、目录身份变化仍拒绝旧计划。普通包计划使用新的指纹域，旧未执行计划需重新生成，不增加兼容分支或迁移。
- 单包卸载和纯卸载批量意图依据项目锁定依赖图计算，不读取仓库索引、不重选保留包版本、不下载保留包，未知来源不阻挡保留已安装包。循环依赖有界遍历、共享依赖保留、不再可达的锁定包按原规则移除；已有缺失依赖不由卸载自动修复。
- 保留现有单包移除直接声明而仍保留被依赖包的语义；批量移除仍拒绝被保留包依赖的目标。不描述为所有卸载语义均与 v3 一致。
- 安装/更新及混合意图需要的来源、归档/缓存摘要、目标路径、冻结 ChangeSet、旧资产清理内容证据、回滚和恢复保持。Unity 版本迁移明确保留其原有内容快照，避免共享读取函数扩大本轮变更范围。

## 失败轮次与限制

- 最初默认沙箱环境的 VPM 测试 166 通过、2 项缓存元数据发布 IO 失败、3 忽略。真实 Windows 用户环境的最终整组通过，保留 `sandbox-vpm.log`，未放宽缓存校验。
- 最初新增的正式端点 RPC 夹具因运行中的 Core 占用端点而返回 `AlreadyRunning`，未连接或写入用户 Core。该新增测试改用项目已有的隔离数据库 Plan/Apply 夹具；临时 RPC 测试代码已删除，既有 RPC 文件无差异。`rpc-targeted.log` 保留该未通过记录，不能作为 RPC 通过证据。
- 新夹具初次缺少 trait 导入；另一次错误地假定正常注册入口会留下未建索引状态。修正为真实启动初始化入口后保留“不完整索引”断言，最终整组通过。中间编译和失败日志均保留，未删业务断言以通过测试。
- GUI 源码未变，未新增加载/错误弹窗或页面提示。未运行浏览器、完整 workspace、Hosted CI 或 Linux/macOS 原生回归；未执行实际项目安装/卸载，也未重启实际 Core/GUI。本记录不扩大为 H7 签收。
