# 项目候选可见性修正

2026-11-08，所有者明确关闭的软件包来源、存储库与版本应先被 Core 筛出可见候选，不应以禁用选项发送给 GUI。随后澄清安装事实与来源可见性无关：已安装包保留；关闭来源与本地缺少来源在来源判断上相同，没有任何可见来源则显示未知来源，有其他可见来源则仍显示那些来源。

## 修改范围

- `alcomd-vpm` 统一在入口过滤来源与预发布策略，再生成 summary IDs、providers、名称/链接和版本记录。预发布关闭时，显式 source 查询及已安装的预发布版本也不会作为可选版本记录返回。项目锁定版本与直接依赖仍是项目事实。
- 完整注册清单仍用于管理和筛选设置；候选来源只由 Core 返回的可见 providers 决定，不能从注册清单推断有来源。关闭来源与缺失目录的已安装包 summary 逐项相等；其他可见 provider 仍可提供候选。
- GUI 无 providers 时显示“未知来源”；新 settings revision 不再复用旧 revision 的候选展示。等待新读取时沿用现有列表 Loading，读取完成后恢复安装事实与当前来源。
- 同步获批 ExecPlan、Schema 说明和 39 项语义向量中的相关预期/测试引用。RPC wire shape、权限、持久结构、Core resolver/Plan/Apply 与已安装项目内容未改；有意改变的是获所有者明确纠正的候选读视图语义。

## 验证结果

- `cargo fmt --all -- --check`、受影响 `alcomd-vpm --all-targets` 严格 Clippy、全工作区 `npm run check` / `npm run build` 和差异空白检查通过。
- Core 候选定向测试 25/25 通过；真实 Windows 完整 `alcomd-vpm` 163 通过、3 项既有显式忽略，含 resolver、安装 staging 等现有回归。沙箱首轮为 161 通过、2 项未改动缓存测试 `CacheError::Io`；相同代码与二进制在真实用户环境全通过，未改动缓存逻辑或放宽断言。增量编译的硬链接复制警告保留。
- `alcomd-application` 候选查询 4/4，公开候选合同 5/5 通过。权限、分页/游标、wire shape 与字段拒绝断言保持。
- 软件包候选、工作区和排序浏览器 61/61 通过；补充的跨设置修订延迟测试 1/1 通过，合计 62 项，零自动重试、零跳过。覆盖关闭/重开来源、已安装包未知来源、预发布排除/开启、分页/来源排序、版本选择、Plan/Apply 与批量操作。
- 延迟测试早期两轮分别误用了初始 revision=1 的假设、以及在产品既定 Loading 期间断言安装行立即出现。改为记录夹具实际首读 revision；等待期间断言无旧 metadata 且显示 Loading，返回后断言安装版本与未知来源。两次只改夹具/测试，未放宽可见性隔离断言。
