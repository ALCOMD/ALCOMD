# M7 软件包卸载确认修正

日期：2026-11-09。所有者已明确回复“批准，按方案修复”，以下窄合同获批。仅推进M7，不改变H7签收。

## 问题与既有行为

Test-Avatar中Avatars在直接依赖及锁定表里，同时被其他已安装包依赖。当前单包卸载只移除其直接声明，随后沿剩余根依赖遍历，又保留了Avatars，产生零个包mutation；GUI只按mutation判断，于是显示“软件包已是最新版本”。Base只在锁定表里，当前卸载错误地要求存在直接声明，因此返回package_not_found；既有失败呈现策略使页面无弹窗。

这不是两个按钮绑定错误。此前性能修正保留了旧卸载语义，没有补齐v3行为。只读审计确认v3按已安装记录接受卸载，并将仍依赖目标的包列入确认信息。仅作行为审计，不复制或移植参考仓库源码。

## 已批准的窄合同

1. 单包卸载和纯移除批量意图均按locked中的已安装记录确认目标存在，允许移除传递依赖。明确请求的包必须成为remove mutation；移除其直接声明和锁定记录，避免生成“只撤声明”的伪卸载。不存在于locked中的目标继续返回package_not_found。
2. 使用本地锁定图及未锁定本地包的清单依赖，不读取仓库、不重新选版本、不下载、不扫描payload。不自动级联删除依赖目标的其他包；仅清理所选目标旧依赖闭包中不再使用的包，无关孤立包保留，共享依赖及剩余包版本/元数据保持。保留包已有缺失依赖不自动修复。清理范围依所有者后续四处缺口修正授权更新。
3. 为现有ChangeSet增加可选removalConflicts数组，每项为{packageId, requiredBy:[{packageId,range}]}。只包含本计划移除的目标及仍保留的依赖方，去重、确定排序；总依赖关系最多4096，与既有edge界限一致。无冲突时字段省略。Core计算并纳入持久化不可变计划及摘要；SDK/协议/Schema/GUI配套，不引入新表、权限、RPC方法或生产依赖。
4. GUI沿用现有“应用软件包更改？”确认框，列出拟移除项及依赖冲突，说明继续会使所列包缺少依赖。用户取消不写项目，明确Apply后执行该冻结计划。仅此单包/纯卸载计划允许所列依赖缺失；混合意图、安装、升级、解析及Unity校验继续沿用既有拒绝边界。实际失败处理保持所有者此前要求的现状，不新增页面提示或错误弹窗。
5. 沿用ChangeSet formatVersion 4，通过上述可选字段承载冲突，不迁移数据库或兼容双写。Apply复验项目身份、清单、包目录身份/元数据、修订及冻结证据；不重新求解、不自动扩大移除范围。配套同步计划恢复和序列化边界。无冲突旧计划不获得新冲突授权。

## 验收

- 独立合成已安装图覆盖直接包仍被依赖、传递包、独立包、共享依赖、循环、批量互依赖及未知来源；无网络/目录内容扫描。确认目标实际进入移除列表，保留包及原依赖边不会被静默改写。
- Core生成冲突的排序、有界性、序列化/摘要和实际Plan/Apply事务回归；取消零项目写入、Apply只执行已审阅项，清单或包身份变化拒绝旧计划。真实用户项目只读核对，不实际卸载SDK。
- GUI验证Avatars/Base均出现正常确认框和明确冲突、取消不Apply、确认仅一次Apply，正常更新的零变更提示继续成立；保持100ms页面导航和原生请求隔离。
- 受影响Rust测试、fmt/严格Clippy、公开形状/Schema及仓库检查、前端检查/生产构建和相关浏览器回归。按实际结果记录，不把夹具当作原生或H7签收。

这是公共RPC响应及卸载语义的窄修订，已按项目AGENTS.md的人工审批边界获批。不复制v3/vrc-get实现，不改变本计划以外的依赖拒绝边界。

本节之后的全面复查又发现批量和恢复等组合入口的七组差异；所有者已授权按[七项合同](M7-vpm-seven-gaps.md)继续修正。以下保留四项当时范围，不作为全部入口已经对齐的依据。

所有者随后明确要求“把这四处缺口都按v3的行为修复，完成相关验证，再更新Core和GUI”。据此继续本M7：

- 只枚举Packages直属目录，有界读取未锁定本地包清单，纳入依赖保护、已有removalConflicts和项目指纹，不扫描payload。新增/删除/改变本地包清单使旧计划失效；普通包指纹域更新，旧未执行计划需重建，不迁移或并行兼容旧依据。Unity迁移原内容快照域保持。
- 卸载仅清理明确目标及其旧依赖闭包中不再使用的锁定包，无关孤立包保留。共享依赖和本地包依赖作保留根，明确请求的目标仍可经原冲突确认卸载。

- 使用独立合成项目验证四个反例、显式冲突、元数据/目录变化、实际Apply与恢复；复跑受影响门禁，构建后备份并更新原Core/GUI，保留数据/profile。不实际卸载用户SDK，不提交或推送，不扩大H7/M11范围。
