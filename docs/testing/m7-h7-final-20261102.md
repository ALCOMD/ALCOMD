### 定位与最小修复

失败在 `wheelIntoView` 固定把指针放到外层视口中心，单次真实 wheel 后要求外层 scrollTop 变化。
源码核对发现，中心可能落在内嵌 Unity 安装表格的水平滚动条上；OverlayScrollbars 的该命中区会 `preventDefault`，
嵌套表格不能竖滚时外层仍为 0。本地原 640px 用例 **3/0** 仅表示当前 Windows 几何没有自然命中该情况，不能排除 Ubuntu 失败。
新增确定性回归将现有嵌套条移到中心、先证明命中及目标尚不可达：旧 helper **0/1**，复现同一 scrollTop=0 超时；
修正后该回归 **1/0**。这证明一个与远端表现一致的测试缺陷；精确远端命中仍为推断，不把初始化时序或字体差异写成已证实根因。

发送 wheel 前用公开 DOM 命中检查，选属于预期外层内容、不是嵌套视口或滚动条的点。
保留真实 wheel、每次位移、最终几何与 trial-click 断言，新增嵌套列表/document 不滚动的保护；不增加重试、JS scrollTop/scrollIntoView 或生产旁路。
