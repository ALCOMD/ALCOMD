# M7 仓库清单资格与软件包可见性修复

2026-11-10 所有者报告 Nadena 缺失 Modular Avatar - Resonite support，lilxyzw 全部软件包在项目管理中消失，并要求检查同类问题。仅推进本 M7 项；参考 v3 只读审计，无源码移植。

## 原因与实施合同

两份实际仓库快照分别含 4 包/397 版本与 11 包/139 版本，其中 Resonite 的 42 版本及 lilxyzw 全部 139 版本缺省 author。普通读取保留行，但 resolver 解析要求 author.name，最终候选目录排除这些行。显示名及描述也不应作为安装资格。Unity 官方将 author 定义为可选 object/string、displayName/description 定义为推荐；VPM 文档的发布字段清单更严格，但已有仓库及 v3 的实际消费行为接受缺省。此修复采用消费语义，不做发布清单审查。

- 作者、显示名、描述使用现有长度边界归一化；缺省/无效展示字段不使安装候选消失。作者真实缺省保存 NULL，不伪造作者。对象作者和字符串作者均可读取。
- 包 ID、SemVer、映射身份、下载来源、依赖、Unity、撤回、旧资源声明及冻结 Plan/Apply 的实际业务校验保持。
- State32 只移除 resolver-ready INSERT/UPDATE 触发器对 display_name/author_name 非空要求，保留其余约束及列长度边界。仅对含 resolver_metadata_invalid 观察的仓库标记待重新索引并清空 HTTP validators，避免 304 保留错误旧判断；不删除仓库、版本、归档摘要、设置或用户项目。
- 后续人工/到期刷新遇到解析失败观察不使用条件 HTTP 读取，使解析规则修正可生效；健康索引保留条件请求及既有刷新节流。
- 不改公开 RPC 形状、权限、Config 或 Extension API，无新增依赖。所有者于本轮明确批准 State32 修正方案；未经另行更新授权不替换运行 Core、不迁移真实数据库；旧 Core 会拒绝 State32 数据，需使用升级前备份回退。

## 验证与交付

冻结三份原始仓库的逐包代表版本及来源摘要；增加完整读取→Store→resolver/candidate 链路回归，展示缺省/无效及真实非法业务字段对照，旧索引修复、健康304及迁移保全回归。对现有公开仓库做有界只读数据审计，实际范围与不能读取项如实记录。定向 Rust、严格 Clippy、fmt/xtask 及独立 Core 构建。GUI 未改动，无真实软件包操作，不提交或推送。本计划及 State32 已获所有者批准，程序更新另行执行。

## 同类数据审计

当前 30 个匿名公开仓库均成功有界读取，共 4,630 条版本。892 条记录涉及 28 个不同软件包缺省 author。另有 VRM Converter 仓库的 UniGLTF 六版本使用 legacyFiles 的 null GUID；官方 VPM 支持不提供 GUID 的路径声明，统一归一化为已有空 GUID 表示，实际清理范围、路径/链接/内容证据和冻结事务检查保持。原始发布方声明不改写，不伪造 GUID。最终 4,630 条均通过完整 parse→Store→resolver/candidate 链路，不将此结果解释为对所有归档/Unity/实际依赖组合的安装验证。

审批问题已说明只移除作者/显示名的非空要求并重建错误旧索引，所有者回答“批准 State32 修正方案”；没有因此授权程序更新、提交、推送或真实项目操作。
