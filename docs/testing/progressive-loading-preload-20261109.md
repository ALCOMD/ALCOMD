## 原批次最终行为

- 共享 `PreloadCache` 和意图 hook 用于主导航、资源分类、只读导航按钮及软件包版本选择。悬停 80ms 开始，键盘聚焦即时开始；悬停、焦点、已打开交互任一有效即保活，全部离开 3 秒后清理，回入取消计时。
- 点击接管同一请求，前台不受推测性队列额度阻塞；不预先挂载隐藏页面，不创建 Plan/Apply 或扩展会话。最多 2 个推测任务，闲置数据按 16 项及约 2MiB 序列化容量淘汰，实际交互中的数据不因闲置预算移除。
- 退出/来源改变/连接与资源修订变化丢弃准备状态，迟到结果不得回填。不能取消的已发 RPC 实际结束前仍占任务额度，包含元数据返回后独立挂起的列表读取。可见页面接管后不被原按钮的离开清理。
- 页面标题和已知导航先显示。关键数据未就绪时用主体顶部进度条；只剩列表时保留表头，使用表格进度条，二者互斥。项目列表/卡片、包列表、资源/模板、任务、日志、仓库详情、项目备份和设置 Unity 列表按相应边界加载；关于页静态信息也先显示。后台刷新保留现有内容。
- 100ms 导航和菜单展开上限保留；具备局部加载壳的页面可以更早切换。160ms 短读取指示延时保留。纯表格资源页由表格视口滚动，表头保持固定；详情与表格混合页保留整体内容滚动。

## 失败轮次与修正依据

早期 `browser-first`、`browser-focused`、`browser-second`、`browser-third` 保留调试证据；首轮中断，不作完整结果统计。发现并修正共享缓存被 StrictMode effect 演练永久停用、非挂起首次加载 effect 随 settled 变化过早清理、取消菜单后迟到准备继续触发打开准备，以及丢弃元数据时过早释放其子读取额度的问题。临时读取诊断代码已移除。

夹具原本已有仓库等待门，新测试曾重复设置第二道门，现复用原门。按新要求更新了原来“加载时标题隐藏/没有表头/必须保留旧页至 99ms”的断言，保留 100ms 上限、焦点及迟到结果检查。

另外三条旧包测试与已接受的行为冲突：版本标签要求附加来源、仓库目录不完整时禁止本地卸载、传递包禁止显式卸载。当前基线已有纯版本标签和本地锁定记录卸载语义；本次只更新测试为这些既有有效合同，并增加显式审阅且不自动 Apply 的断言，没有改动生产卸载资格。传递包旧禁用断言还曾在异步资格未到时偶然通过，末轮等待真实资格后暴露。
