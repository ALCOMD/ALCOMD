# State24 repository archive pins

State24 retains existing repositories, versions, projects, and plans. The `resolver_indexed` flag marks repositories whose latest full index was parsed under the revised manifest rules. Existing snapshots start unindexed. Core fetches a full index before marking them indexed. Unindexed snapshots with package versions require reindexing for catalog completeness. Newly registered repositories index the initial response. A completed index can contain versions that fail manifest validation. Those versions remain visible when browsing the repository and are excluded from package resolution.

Resolver metadata allows a missing author email and allows an HTTP(S) artifact to omit a publisher digest. The repository parser treats a malformed publisher digest as absent. A valid publisher digest remains authoritative. Core stores a locally derived 32-byte digest in `local_zip_sha256` only when the selected HTTP(S) artifact lacks a valid publisher digest. It binds the digest to the current repository owner and source identity, package ID, version, manifest fingerprint, and artifact URL. A repeat that observes a different digest fails. Full refreshes retain a local pin only for an unchanged artifact binding. Pin persistence is internal to the version row. Repository revisions and events describe index changes.
